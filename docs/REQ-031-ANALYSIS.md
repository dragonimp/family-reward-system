## 2. 目标与现状差距

目标是让已登录的家长用户在家加分 Web 端任意页面快速提交问题、建议或咨询，并可查看自己提交的反馈及处理状态；反馈统一进入 Atlas 的项目反馈队列，避免家加分再建设一套孤立的处理后台。

当前差距如下：

| 能力 | 家加分现状 | Atlas 参考能力 | 本需求结论 |
| --- | --- | --- | --- |
| 反馈入口 | 无 | 页面右侧可收起、可拖动的悬浮入口 | Web 全局布局增加反馈入口，移动端避让底部导航 |
| 提交表单 | 无 | 建议/缺陷、标题、内容、提交人、联系方式 | 增加建议/问题/咨询三类；登录用户信息自动带入 |
| 页面上下文 | 无 | 自动采集地址、路径、标题、视口、浏览器、时间等 | 自动采集但提交前可展开查看，不采集令牌或表单值 |
| 处理队列 | 无 | `POST /api/feedback` 进入 Atlas 调度 | 家加分后端代理到 Atlas，不在本地复制反馈表 |
| 我的反馈 | 无 | `GET /api/feedback/mine` | 展示当前用户提交记录、状态、回复和更新时间 |
| 状态闭环 | 无 | 待跟进、处理中、待发布复测、已解决、已驳回、已转化 | 前端只读展示 Atlas 状态，不允许用户自行关闭 |

## 3. 用户流程与交互口径

### 3.1 提交反馈

1. 登录且完成家加分身份选择的用户，在任意 Web 页面都能看到“问题反馈”入口。
2. 点击后打开模态框，默认类型为“建议”；可切换“问题/缺陷”和“咨询”。
3. 必填项为类型、标题和内容；称呼从当前统一身份的显示名带入，联系方式可选。
4. 系统自动带入页面标题、完整 URL、路径、视口、浏览器和采集时间。上下文默认折叠，用户可在提交前查看。
5. 提交按钮在请求期间禁用，避免重复提交；成功后显示反馈编号和“已进入处理队列”，失败时保留已填写内容并允许重试。
6. 同一页面的重复点击不能生成并发重复请求；后端为每次提交生成稳定来源记录号并透传给 Atlas，以支持网络重试幂等。

### 3.2 我的反馈

- 反馈窗口提供“提交反馈 / 我的反馈”两个页签；首期不新增主导航一级菜单。
- 列表按创建时间倒序，展示类型、标题、状态、创建/更新时间、处理回复；无记录时展示明确空状态。
- 状态文案与 Atlas 保持一致：`pending` 待跟进、`scheduled` 待调度、`processing` 处理中、`pending_release` 待发布复测、`released_verifying` 生产复测中、`reviewed` 已解决、`rejected` 已驳回、`converted` 已转化。
- 只允许读取当前登录用户创建的反馈；不得按前端传入的用户名查询他人记录。

### 3.3 终端范围

- 本期范围为家长 Web 端桌面、平板和手机布局。
- 儿童手表 `/watch` 不增加反馈入口。手表交互面积小且使用设备令牌，不具备当前 Atlas 用户身份；如需儿童问题上报，应另立需求并定义家长可见性与未成年人数据边界。

## 4. 数据与接口设计

### 4.1 集成原则

Atlas 是反馈事实源和处理队列。家加分不新增 `feedback` 数据表，不保存处理状态副本；由 ASP.NET Core 后端提供同源代理，统一补全并约束项目、应用、提交人和来源字段。这样可避免浏览器直接跨域访问 Atlas、客户端伪造 `project_code`，也避免两套状态漂移。

建议配置：

- `FAMILY_REWARD_ATLAS_URL`：Atlas 服务基址，由开发/测试/生产环境分别配置；禁止硬编码生产地址。
- 固定项目编号：`family-reward`。
- 应用编号：优先使用 Atlas 项目中已登记的真实 app code；在 Atlas 恢复前不猜测为 `happylife` 或 `happylife-watch`。
- 上游请求超时建议 8 秒；不得把 Atlas 内部错误堆栈直接返回浏览器。

### 4.2 家加分对前端接口

`POST /api/feedback`

```json
{
  "feedbackType": "suggestion",
  "title": "希望支持批量选择规则",
  "content": "积分操作时希望一次选择多个规则。",
  "submitterContact": "user@example.com",
  "source": {
    "url": "https://happylife.ai.impx.net/reward",
    "pageTitle": "家加分",
    "path": "/reward",
    "viewport": "390x844",
    "userAgent": "...",
    "capturedAt": "2026-08-16T10:00:00.000Z"
  }
}
```

服务端行为：

- 通过现有 AgentIdentity 身份解析当前用户，未登录返回 401；提交人显示名和稳定用户 ID 以服务端身份为准。
- 校验 `feedbackType` 白名单，标题去首尾空格后 1–200 字，内容 1–5000 字，联系方式最多 160 字。
- 只接受 `http/https` 且属于家加分允许域名的来源 URL；清除 URL 中可能含令牌的敏感查询参数，限制 `userAgent` 和页面上下文字段长度。
- 转换为 Atlas `POST /api/feedback` 所需字段：`project_code`、真实 `app_code`、`feedback_type`、`title`、`content`、`submitter_name`、`submitter_contact`、`source_url`、`page_context`、`source_metadata`、`source_type=user_report`、`source_system=family-reward-web`、`submitter_type=external_user`。
- 返回稳定的反馈 ID、类型、标题、状态和创建时间；Atlas 不可用返回 502/503 和可重试提示。

`GET /api/feedback/mine?take=50`

- 服务端以当前用户稳定 ID代理 Atlas 的“我的反馈”查询，`take` 限制为 1–100。
- 仅返回界面所需字段，不向用户暴露调度内部载荷、执行器 ID 或敏感来源元数据。

### 4.3 失败与幂等

- 浏览器每次打开表单生成 `crypto.randomUUID()` 作为 `sourceRecordId`，同一次提交重试复用；服务端将其限定在当前用户、应用和项目范围后传给 Atlas。
- Atlas 超时不应自动假定提交失败；用户重试复用来源记录号，由 Atlas 的 `source_system + source_record_id` 幂等规则返回已有反馈。
- “我的反馈”加载失败不阻断提交页；提交失败不清空用户输入。

## 5. 隐私、安全与可访问性

- 自动上下文禁止采集 Cookie、Authorization、localStorage、页面表单值、选中文本、家庭成员积分明细和孩子身份信息。参考控件会采集选中文本，本项目明确不沿用该项，避免意外上传儿童相关内容。
- URL 提交前移除 `token`、`code`、`auth`、`key` 等敏感查询参数；服务端再次净化，不能只依赖前端。
- 文本按纯文本存储和展示，回复内容不得直接作为 HTML 注入。
- 入口、关闭按钮、类型切换、页签和提交按钮均需键盘可达并有可访问名称；模态框打开后聚焦标题，Esc 关闭，关闭后焦点返回入口。
- 移动端弹窗不得被底部导航遮挡；错误和成功信息使用可读文本并通过 `aria-live` 通知。
- 对同一用户/IP配置合理频率限制；具体阈值遵循 Atlas 和项目公约，Atlas 不可用时不得在内存中无限排队或写入日志正文。

## 6. 验收标准

1. 已登录家长可在桌面、平板和手机任意业务页面打开反馈窗口，儿童手表页面不出现该入口。
2. 建议、问题/缺陷、咨询三类均可提交；标题和内容为空、字段超长或类型非法时有明确校验提示且不会请求 Atlas。
3. 成功提交后 Atlas 中产生属于 `family-reward` 和正确 app code 的反馈，来源用户、页面和稳定记录号可追溯，并进入 Atlas 既有调度流程。
4. 网络超时后用同一来源记录号重试只产生一条反馈，不出现重复记录。
5. “我的反馈”只返回当前登录用户记录，能正确展示全部既定状态、处理回复、创建和更新时间；另一用户无法读取。
6. 页面上下文包含净化后的地址、页面标题、路径、视口、浏览器和时间，不包含令牌、Cookie、localStorage、表单值、选中文本或孩子积分数据。
7. Atlas 不可用时提交页保留输入并提示稍后重试，“我的反馈”失败不影响继续填写。
8. 模态框支持键盘焦点、Esc、可访问名称和 `aria-live`；移动端不被底部导航遮挡。
9. ASP.NET Core 构建、前端 lint/生产构建、代理接口单元或集成测试、Atlas 开发环境提交与“我的反馈”闭环均通过。
10. 生产发布和复测只能由受控部署任务执行；当前需求实现任务不得直接部署或重启生产服务。
