# 家加分信用分设计稿

## 目标与定位

信用分记录孩子对约定的履行情况，帮助家长和孩子回顾、改进。它与现有可兑换积分、现金和物品账户分开：不能兑换、转账、折现，也不自动影响已有奖励或积分余额。首期不用于好友排行、跨家庭公开展示或自动限制孩子使用功能。

现有孩子积分账户按全局 `profile_key` 在多个家庭组共享。信用分也归属于同一个孩子档案，但只有孩子本人和其归属家长可以查看详情；圈子成员及好友不因能看到积分而取得信用记录权限。

## 首期规则

| 项目 | 设计口径 |
| --- | --- |
| 开通 | 由归属家长对孩子主动开通；已有孩子保持“未开通”，迁移不自动生成信用记录 |
| 起始值与范围 | 开通时记一条起始事件，80 分；始终限制在 0–100 分 |
| 增分 | 按时完成双方确认的约定 +2；主动补救已逾期约定 +1；家长可选择“诚实说明”“承担责任”等原因并给出 1–3 分 |
| 减分 | 已确认的约定逾期 -2；故意虚报完成情况 -5。系统提醒逾期，但首期不自动扣分，须家长确认 |
| 频率 | 同一约定的同一状态变更只记一次；同一天同类手工原因最多一次；单日手工增减绝对值合计最多 10 分 |
| 家长裁量 | 家长可以选择原因和备注进行 ±1–5 分调整；必须展示变更前后分值，不能直接覆盖余额 |
| 撤销 | 错记通过反向事件撤销，保留原事件、操作人、时间和撤销关系 |

“约定”最少包含标题、到期时间、孩子、创建家长和状态；孩子可标记完成并说明，家长确认完成或逾期。孩子对扣分可以发起一次异议，家长确认后撤销或保留并填写解释。起始值、各原因分值和上限作为首期产品默认值，上线前需由家庭使用场景验收，不从旧积分流水推算历史信用。

## 页面与流程

1. 家长在孩子详情页开通信用分，看到当前分数、最近变动和“新建约定”。首页孩子卡片增加一个独立信用分指标；未开通时显示“未开通”，不显示 0 分。
2. 新建约定时写清事项和截止时间。孩子在自己的手表或手机页面只看到自己的约定、分数及每次变更原因，可以申请完成或提出异议，不能自行加减分。
3. 家长确认完成、逾期或手工调整时，界面先展示原因、分值和变更后的结果，再提交。提交成功后显示一条可追溯记录。
4. 信用分低于 60 时仅提示家长与孩子讨论可执行的改进约定；达到 90 时可展示鼓励提示。首期不据此自动扣积分、拒绝兑换或评价孩子人格。

手表首屏空间有限，可在积分详情中增加“信用 86”入口；详情列表按时间倒序显示最近记录。公开好友榜、圈子榜、成长报告默认不纳入信用分。

## 数据与接口

- `child_credit_accounts`：以 `profile_key` 为主键，保存当前分值、开通时间和版本号。账户只能经信用事件事务更新。
- `child_credit_events`：不可变流水，包含事件 ID、孩子档案键、约定 ID（可空）、原因代码、分值变化、变更前后值、家长操作人、备注、创建时间、幂等键及撤销来源事件 ID。
- `child_commitments`：孩子档案键、标题、截止时间、创建家长、状态、完成申请时间、确认时间；状态变更与信用事件在同一数据库事务内提交。
- 家长接口：查询本人孩子信用概览及流水、开通、创建约定、确认状态、手工调整、撤销、处理异议。孩子接口：查询本人数据、提交完成申请和异议。所有写入在服务端验证孩子归属、事件状态、分值边界及幂等键。
- 新增 `/api/credit/overview` 返回归属孩子的信用分展示字段，家长页面按 `profileKey` 合并；现有 `/api/children`、`/api/transactions` 和积分 `score` 字段保持原有语义。信用流水使用独立接口，避免旧客户端把信用变化当作可兑换积分。

## 上线与验收

结构变更使用独立、带唯一编号和校验和的一次性迁移，由部署脚本在备份后执行；应用启动和查询不初始化或回填信用数据。旧孩子仅在家长主动开通时创建起始事件，新孩子也不自动开通。迁移失败回滚事务，已完成迁移重复部署跳过。

验收至少覆盖：家长只能修改本人孩子；跨家庭组仍指向同一孩子信用账户；圈子成员与好友不能读取信用流水；重复提交不重复计分；并发操作不越界；撤销保留审计；旧积分与兑换结果不变；未开通孩子显示正确；手机、iPad 和手表页面可读。

用户已确认以守约评分为信用分口径。家长 Web、iPhone/iPad 原生端和手表端均提供独立入口，正式可用性以部署及 TestFlight 读回为准。

API 新增 Atlas 授权排空控制，只有配置 `AtlasRelease:ControlApplicationId` 时开放控制路由；控制请求需携带用户中心签发的 `release:upgrade` 服务令牌。这样后续 Atlas 升级可以等待业务请求结束并独立核对运行版本。
