# 亲子互动首版（2026-10-05）

## 目标与入口

家长在网页和原生 iPhone / iPad 的“亲子互动”里发起、倾听与安排；孩子在原生 Apple Watch 或手表网页端发起和回复。四种互动都绑定现有孩子档案和家长身份，不参与积分、信用分、排行或 AI 评价。

| 互动 | 发起 | 关键步骤 | 完成条件 |
| --- | --- | --- | --- |
| 孩子决定的十分钟 | 双方 | 孩子选活动；家长预约三个月内的时间；双方可留感想 | 预约后任一方完成 |
| 先听我说 | 双方 | 发起时选择“只想说说 / 想要安慰 / 一起想办法”；双方交流 | 双方都留言后任一方完成 |
| 吵架后的重连 | 双方 | 双方各自写感受或期待；避免评判和扣分 | 双方都留下记录后完成 |
| 家庭小会议 | 双方 | 家长与孩子各提交提议；家长选择一个安排试行七天；双方复盘 | 七天后双方都复盘，家长结束试行 |

本版会议是**一个孩子和其绑定家长的私密小会议**。多孩子／多监护人共同参加、通知提醒和日历邀请不在本版范围；后续扩展前需先设计参与者授权和可见性，避免把私密发言自动公开给兄弟姐妹。

## 数据与权限

- `family_connections` 保存种类、孩子档案键、绑定家长、阶段、预约／复盘时间、试行安排和幂等请求号。
- `family_connection_entries` 保存双方原文和作者角色；不触发积分流水。
- 网页和 iOS 使用用户中心登录后的家长档案，并查 `child_user_bindings`。手表使用独立设备令牌，并限定当前绑定的孩子和家长；列表及读写操作再次检查绑定。
- 所有写入要求 UUID 请求号或合法阶段；重复请求返回同一结果，冲突或越权拒绝。内容长度限制 2–500 字。
- 删除或解绑孩子后，旧记录不再可从接口读取。恢复授权前需人工评估数据保留和隐私要求。

## 迁移与发布

`20261005-family-connections-v1.sql` 只新增表和索引，不读取或改写既有积分、信用及成员数据。由 `scripts/run-db-migrations.sh` 在数据库备份后一次性执行；迁移脚本的内容校验和与完成记录在同一事务中保存。已执行脚本不修改，如需调整另建迁移。发布顺序为 GitHub 同步、Atlas 包构建与发布、生产备份及迁移、Atlas API/Web 升级、健康和权限读回，再发布 iOS / watchOS TestFlight 构建。API 回滚到旧版仍可保留新增表；有用户记录后不执行删表回滚。
