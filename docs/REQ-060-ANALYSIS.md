## 2. 目标与现状结论

目标是在儿童手表端提供流星、雪花、花朵、库洛米 IP、我的世界五款动态主题。主题默认锁定；儿童只能发起使用申请，家长在 Web 端通过公共 `agent-pay` 支付中心完成购买，服务端确认支付成功后，孩子才能选择并使用对应表盘。

当前系统仅具备“自由切换静态表盘”的基础，付费闭环尚不存在。因此 `TASK-221` 可凭本文与提交证据关闭，`REQ-060` 不可关闭。

| 能力 | 当前实现 | REQ-060 差距 |
| --- | --- | --- |
| 表盘目录 | `/watch` 内硬编码 6 款 CSS 主题 | 无动态效果、商品/价格、锁定标记和上架状态 |
| 表盘偏好 | `watch_face_preferences` 仅保存孩子当前 `watch_face` | 无购买权益；`PUT /api/watch/settings` 可由有效设备令牌直接切换任意白名单主题 |
| 儿童申请 | 仅有积分奖励申请 `/api/watch/requests` | 语义、审批和金额模型均不同，不应复用为购买申请 |
| 家长通知 | 仅有好友通知和积分操作页待确认申请 | 无表盘申请通知、未读状态、购买入口和处理结果 |
| 支付 | 仓库内无 `agent-pay` 客户端、支付订单、回调或退款模型 | 需通过公共组件的正式应用接口接入，禁止浏览器伪造支付成功或直写外部数据库 |
| 授权校验 | 设备令牌可读写当前孩子表盘偏好 | 保存和渲染前均未校验孩子是否拥有该付费主题 |

## 3. 产品与交互口径

### 3.1 表盘目录与锁定状态

1. 五款主题采用稳定键：建议 `meteor`、`snow`、`flowers`、`kuromi`、`world_dynamic`。显示名、价格、币种、动态效果版本和上架状态由服务端目录返回，前端不得自行决定价格。
2. 未购买时卡片显示锁图标、价格和“申请解锁”；不能预览为当前表盘，也不能通过手工调用设置接口启用。可展示静态缩略图或受限短预览，但预览不得写入偏好。
3. 点击“申请解锁”先显示原需求文案：“作业做完了吗？做完了再叫爸爸妈妈出来解锁”。儿童确认后创建申请；取消不产生记录。
4. 同一孩子、同一主题存在待处理申请时再次点击应返回原申请，不重复通知家长；界面显示“已申请，等爸爸妈妈处理”。
5. 权益生效后显示“已解锁”，儿童可选择并保存；支付成功不强制切换当前表盘，避免远程改变孩子正在使用的界面。
6. 动态效果只在表盘首页运行，进入菜单/表单、页面隐藏或低电量/降级模式时暂停。支持 `prefers-reduced-motion`，并提供静态回退，避免低端 WebView 卡顿和耗电异常。

### 3.2 家长通知与购买

1. 家长 Web 增加独立的“表盘解锁申请”通知或统一通知类型，至少显示孩子、主题、申请时间、价格、状态和“去解锁”。不得混入积分入账审批接口。
2. 通知仅对该孩子的所属家长可见。若孩子关联多个有权家长，所有有权家长可见同一申请，但只能生成一个有效支付结果。
3. 家长点击“去解锁”后，由家庭积分后端创建内部购买单，再通过公共 `agent-pay` 服务端接口创建支付单。前端只接收支付组件所需的短期会话/跳转参数，不能接触服务密钥。
4. 页面跳转回成功、前端回调或客户端轮询都不能直接授予权益。只有后端验签并核对 `merchantOrderId`、金额、币种、商品和支付状态后，才能原子地把订单置为已支付并授予权益。
5. 支付失败/取消后申请可再次发起支付；支付处理中禁止重复创建无限订单。支付成功后其他家长看到“已由家庭成员解锁”。
6. 退款、撤销和争议订单的产品规则必须在开发前确认。推荐首期保留已授予权益并转人工处理，除非 `agent-pay` 明确提供可靠的退款事件和业务方已确认自动回收规则。

### 3.3 既有用户与兼容性

当前“我的世界”已经是默认且可免费使用的 `world` 主题。REQ-060 又要求“我的世界动态主题”默认锁定，两者存在兼容冲突。建议保留现有静态 `world` 为免费基础主题，新建 `world_dynamic` 作为付费动态版本；不得通过迁移突然锁住孩子当前表盘。其他既有免费主题继续可用，不属于本需求的付费目录。

## 4. 数据与状态模型

建议新增独立模型，不在 `watch_face_preferences` 中用特殊字符串推断是否已付款：

- `watch_face_products`：主题键、名称、效果版本、价格（最小货币单位）、币种、启用状态、排序；商品价格变更需保留订单快照。
- `watch_face_unlock_requests`：孩子 profile key、主题键、申请人设备、状态、创建/更新时间；状态建议 `pending`、`payment_pending`、`unlocked`、`cancelled`、`expired`。
- `watch_face_payment_orders`：内部订单号、申请 ID、付款家长、商品/金额/币种快照、`agent-pay` 外部订单号、支付状态、幂等键、支付/失败/退款时间和脱敏响应摘要。
- `watch_face_entitlements`：孩子 profile key、主题键、来源订单、授予时间、可选撤销时间；对“孩子 + 主题”设唯一约束。
- 通知可新增通用 `parent_notifications`，或创建表盘专用通知表；无论采用哪种方式，通知必须引用同一申请，不能复制成多份可独立付款的业务记录。

关键约束：

- 申请创建：同一孩子/主题最多一个活动申请，数据库唯一约束配合幂等返回。
- 订单创建：客户端提交幂等键；同一申请最多一个 `created/paying` 有效订单。
- 支付回调：以外部事件 ID 去重，事务内锁定订单、校验快照、授予权益并更新申请；重复回调返回成功但不重复授予。
- 表盘设置：`PUT /api/watch/settings` 必须查询目录和权益；不能只依赖手表 UI 隐藏按钮。
- 表盘读取：若历史偏好指向已下架、撤销或无权益主题，返回安全的免费主题，同时保留审计信息以便排查。

## 5. 建议接口边界

具体路径可按项目规范调整，但职责应保持分离：

| 调用方 | 接口 | 作用 |
| --- | --- | --- |
| 手表 | `GET /api/watch/faces` | 返回目录、锁定/已申请/已解锁状态和当前选择 |
| 手表 | `POST /api/watch/face-unlock-requests` | 幂等创建当前孩子的主题申请 |
| 手表 | `PUT /api/watch/settings` | 保存表盘；服务端拒绝未授权付费主题 |
| 家长 Web | `GET /api/watch-face-unlock-requests` | 查询本人名下孩子的申请及未读/订单状态 |
| 家长 Web | `POST /api/watch-face-unlock-requests/{id}/payment-session` | 校验孩子归属并通过后端创建 `agent-pay` 支付会话 |
| 服务端 | `POST /api/payments/agent-pay/webhook` | 验签、查单/核单、幂等授予权益；该路由不使用家长前端鉴权代替支付验签 |
| 家长/手表 | `GET /api/watch-face-unlock-requests/{id}` | 轮询最终状态；仅返回调用身份可见字段 |

支付适配器需隔离 `agent-pay` 的 SDK/协议，配置仅从受控环境读取。日志不得记录服务密钥、完整支付凭据、回调签名原文或儿童敏感标识。

## 6. 动态主题实现约束

- 流星、雪花、花朵优先使用本地 CSS/SVG/Canvas 轻量效果；资源随应用发布，不依赖外部 CDN。
- 库洛米和“我的世界”涉及第三方 IP/商标。获得书面授权并确认素材使用范围前，只能使用内部占位主题键，不能制作、提交或上线仿制角色/游戏素材。若未获授权，产品需更名并替换为原创视觉。
- 单主题应限制同时活动的粒子数量，复用动画对象；页面不可见时停止动画。目标是维持手表触控响应和稳定帧率，而不是追求高粒子密度。
- 内容文字、锁图标和按钮在动画背景上需有稳定遮罩/对比度；动画不能遮挡时间、积分和菜单，也不能成为表达锁定状态的唯一方式。
- 家长虚拟手表预览只能显示孩子真实权益，不得因为家长身份绕过授权；预览模式继续禁止写操作。

## 7. 验收标准

1. 五款付费动态主题均在目录出现，默认显示锁图标、服务端价格和申请按钮；免费既有主题无回归。
2. 儿童点击后看到指定作业提醒；取消不创建申请，确认只创建一个活动申请，重复点击不产生重复通知。
3. 儿童无法调用支付或直接启用锁定主题；手工调用 `PUT /api/watch/settings` 设置未购买主题返回 403/业务拒绝且偏好不变。
4. 有权家长能看到孩子、主题、时间、价格和状态；无权账号及其他家庭不能读取、支付或标记该申请。
5. 家长通过公共 `agent-pay` 组件完成支付；取消、失败、超时不授予权益，前端伪造成功跳转不授予权益。
6. 有效支付回调验签并核对订单号、商品、金额和币种后授予一次权益；重复/乱序回调、重复点击和多家长并发支付不产生重复权益或重复扣款业务单。
7. 权益生效后手表轮询或重新进入即可看到“已解锁”，可选择并在刷新、重启、重新绑定同一孩子设备后保持选择。
8. 现有静态 `world` 用户不被锁定；动态 `world_dynamic` 作为独立商品验证购买。
9. 五款动画在代表性视口 194×368、240×240、320×360、466×466、368×194 下无裁切，页面隐藏和 reduced-motion 时暂停/降级；目标设备无明显输入卡顿或异常耗电。
10. IP 主题上线前具有可审计的授权或替换为原创素材；自动化覆盖权限、金额篡改、回调验签、幂等、并发、持久化和降级，目标平台完成真机回归。

以下事项不阻塞本次需求分析完成，但会阻塞开发验收或上线：

1. `agent-pay` 的正式组件标识、服务端 API/SDK、沙箱环境、鉴权与验签方式、回调重试/查单协议尚未提供。
