## 3. 现状差距与关键决策

代码核对确认当前仅具备以下基础：

- `/watch` 内硬编码六款免费静态 CSS 主题，`watch_face_preferences` 只保存当前主题；
- 有效设备令牌可通过 `PUT /api/watch/settings` 切换白名单主题，服务端没有付费权益校验；
- 儿童积分申请与好友通知可以作为交互参考，但语义和数据模型不适合承载表盘购买；
- 仓库没有 `agent-pay` 客户端、支付订单、验签回调、表盘商品、解锁申请或孩子主题权益。

实施必须保持以下边界：

1. 采用表盘商品、儿童解锁申请、家长通知、内部支付订单和孩子主题权益五类独立模型；申请、订单与权益均需数据库幂等约束。
2. 儿童确认指定作业提示后仅创建申请；儿童端不得创建支付会话、授予权益或直接启用锁定主题。
3. 家庭积分后端调用 `agent-pay` 正式应用接口创建支付会话。只有后端验签并核对订单号、商品、金额、币种和支付状态后，才可在事务中授予一次权益；前端成功跳转不能作为付款证据。
4. `PUT /api/watch/settings` 必须在服务端拒绝未购买主题，不能仅依赖锁图标和隐藏按钮。
5. 现有免费静态 `world` 不得被突然锁定；新增 `world_dynamic` 作为独立付费主题。支付成功只授予权益，不强制切换孩子当前表盘。
6. 流星、雪花、花朵优先使用本地轻量效果，并在页面隐藏、低电量或 `prefers-reduced-motion` 下暂停或静态降级。
7. 库洛米和“我的世界”上线前必须具有可审计的 IP/素材授权；无授权时只能保留内部主题键并改用原创视觉。

## 4. 验收与安全底线

验收至少覆盖五款主题默认锁定、指定确认文案、重复申请幂等、跨家庭拒绝、未购买设置接口拒绝、支付失败不授权、回调验签与金额篡改、重复/乱序回调、多家长并发、刷新/重绑持久化、五类代表性手表视口、动画暂停降级及免费主题无回归。

所有部署、发布和生产服务操作只能由受控部署执行器完成，不属于当前分析 worker。
