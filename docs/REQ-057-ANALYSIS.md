## 4. 应用接口处理流程

项目管理写入能力可用后，应通过正式应用接口执行以下幂等流程：

1. 查询 `family-reward` 项目下 `family-points / xiaotiancai / 1.0.0 (100)` 的应用上架记录；不存在时创建草稿，存在时复用，禁止产生重复版本。
2. 按材料键查询既有资产，计算本地文件 SHA-256；相同哈希直接复用，不同哈希创建新版本并保留旧版本审计记录。
3. 上传文件或登记受控 HTTPS 引用，保存项目、应用、平台、版本、材料键、状态、来源提交、文件哈希、上传人和上传时间。
4. 按第 3 节的真实完成度设置 `ready`、`draft`、`missing` 或 `external_action_required`，禁止把待盖章、待真机或缺证材料批量标成完成。
5. 重新读取应用上架记录，核对返回资产 ID、材料状态和版本归属，并把接口回执附到 Orbit/Atlas 任务证据。

接口不得接收或回显签名私钥、keystore 密码、测试账号密码、完整身份证号码或一次性验证码。

## 5. 验收标准

1. 项目管理“应用上架”栏目能查询到小天才 `1.0.0 (100)`，且归属项目、应用、平台和包名正确。
2. 第 3 节每项材料均有独立资产记录或明确缺项，文件类记录可由 SHA-256 对应回仓库发布包。
3. 重复执行上传不会产生重复版本或重复资产；材料内容变化时产生新版本并保留审计链。
4. APK、图标和介绍图的规格校验通过；法律 URL 可访问，文件和 URL 版本一致。
5. 待盖章免责函、待真机测试报告、软著、APP 备案、法人证件和真机矩阵保持真实未完成状态，不影响已完成材料的上传。
6. 有应用接口返回的上架记录 ID、资产 ID、上传时间、操作者和最终回读快照；仅有仓库文件或 SQL 不算上传完成证据。
7. 全流程不直接写 Atlas 数据库，不部署、不发布、不提审、不操作生产服务。
