# REQ-033 家长端移动智能体对话需求分析

## 1. 事项与分析结论

- Orbit：`gpt_dc202bc7acb84dd887c9f2b6791deacf`
- 需求：`family-reward-REQ-033`（`58e2855d-a3bd-4383-bd7c-d7afd5f9084a`）
- 分析任务：`family-reward-TASK-050`（`f5f05423-748e-44b1-b245-170e3b5492f5`）
- Atlas 功能点引用：`245414ae-7163-46af-82bb-1bb73cf9a63b`
- 事项类型：变更需求；载荷状态：`submitted`

本需求在家长端手机界面增加一个固定于底部的智能体对话输入区。进入应用后仍展示现有仪表盘；家长输入或口述指令并确认发送后，进入独立的对话模式，调用 Orbit 中绑定的“家庭积分应用”智能体并展示可持续的会话消息。输入区左侧的功能菜单负责页面导航、会话操作和返回仪表盘。

本次只完成需求分析和开发拆分，不实施业务代码。`TASK-050` 可在本文及提交证据写回 Atlas 后更新为完成；`REQ-033` 必须保持待开发，直至前后端实现、智能体绑定、测试、受控部署和生产复测全部完成。

## 2. 当前实现与差距

| 能力 | 家加分当前实现 | bigdata 参考实现 | REQ-033 结论 |
| --- | --- | --- | --- |
| 手机首页 | `/dashboard` 展示现有仪表盘 | 对话工作区为独立页面 | 保留仪表盘，不把首页改造成欢迎聊天页 |
| 手机底部区域 | `Layout.tsx` 在 `lg` 以下显示 6 个导航项和“更多” | 移动端通过抽屉选择智能体和会话 | 手机断点下改为“菜单 + 对话输入 + 发送/麦克风”，原导航移入菜单 |
| 语音输入 | `Reward.tsx` 和 `Settings.tsx` 已使用浏览器 SpeechRecognition | 对话输入支持常规文本 | 复用浏览器能力，但需抽成共享语音输入能力；不可自动申请权限或自动发送 |
| 智能体调用 | `/api/agent/invoke` 是单次、非流式、无会话的 OpenAI 兼容转发 | 授权智能体发现、会话、消息历史、SSE 流式对话 | 新增面向 Orbit WebApp 网关的家加分专用会话代理；不继续扩展通用 invoke 充当聊天协议 |
| 智能体选择 | 系统配置保存 endpoint/model/apiKey | 通过稳定 agent ID/code 和 WebApp 路由绑定 | 服务端固定解析“家庭积分应用”的稳定 agent ID/code；前端不得按展示名猜测或允许任意选择 |
| 会话历史 | 无 | 创建、列表、消息、改名、归档、重置上下文 | 首期至少支持当前用户会话创建、消息读取和流式发送；历史列表/新会话由左侧菜单进入 |
| 身份边界 | 后端接口使用 `RequireParentProfile` | bigdata 后端代理 Orbit，前端不直连 | 所有代理接口先校验家长身份，以稳定 app user ID 映射 Orbit 用户，不信任浏览器自报用户名 |

现有 `/api/agent/invoke` 还允许请求体传入 `apiKey`，返回的是上游原始响应，并且异常正文可能直接透出，不符合本需求的固定智能体、最小凭据暴露、会话隔离和流式体验要求。REQ-033 实现时应新增受约束的业务接口，不应让移动前端提交 endpoint、模型、agent ID 或密钥。

## 3. 范围

### 3.1 本期范围

1. 仅对已登录且已选择家长身份的手机端生效；桌面端和平板端现有导航默认保持不变。
2. `/dashboard` 首次渲染保持当前仪表盘内容，底部新增固定对话输入区。
3. 输入区左侧显示功能菜单按钮；菜单至少包含仪表盘、积分操作、交易记录、统计报表、家庭/孩子/规则管理、系统设置、新建会话和历史会话。
4. 默认突出麦克风入口，同时保留可聚焦的文本输入；语音识别结果进入输入框供家长确认和编辑。
5. 用户发送非空指令后创建或复用会话，切换到对话路由并按流式事件逐步展示回复。
6. 对话模式展示用户消息、智能体消息、发送中/工具处理中、失败及重试状态，并保持底部输入区可继续追问。
7. 菜单中的“仪表盘”可随时返回 `/dashboard`；返回不会删除或重置当前会话。
8. 会话、消息和错误都按当前家长用户隔离；同一家庭中的其他家长不因家庭成员关系自动共享私人对话。

### 3.2 非本期范围

- 儿童身份和 `/watch` 手表端对话入口。
- 语音音频上传、服务端语音转写、语音合成朗读和唤醒词常驻监听。
- 前端自由切换智能体、模型、endpoint、密钥或 WebApp bot。
- 在聊天页面重新实现一套积分业务规则；业务动作由“家庭积分应用”智能体及其受控 MCP 工具完成。
- 生产部署、服务重启和智能体配置发布；这些必须走受控部署与 AgentFree Studio 配置流程。

## 4. 手机交互与状态模型

### 4.1 响应式边界

- 手机模式建议使用 `max-width: 639px`（Tailwind `sm` 以下），而不是沿用当前底部导航的 `lg` 以下范围，避免平板也被强制切换为窄屏输入条。
- 输入区固定在应用视口底部并适配 `env(safe-area-inset-bottom)`；主内容增加等高底部留白，不能遮挡仪表盘最后一项或聊天最后一条消息。
- 键盘弹出时使用动态视口高度，输入框和最新消息保持可见；菜单和对话列表采用内部滚动，不造成页面横向滚动。

### 4.2 仪表盘模式

- 页面主体继续渲染当前 Dashboard。
- 底部栏从左到右为：功能菜单、可编辑文本/语音转写框、主操作按钮。
- 空输入时主操作按钮为麦克风；已有文本时切换为发送按钮。麦克风不能在页面加载时自动启动。
- 首次录音前由浏览器请求权限；拒绝、浏览器不支持或识别失败时保留文本输入并给出可关闭提示。
- 语音停止后只写入文本框，不自动调用智能体，避免误识别直接产生积分变更。

### 4.3 对话模式

- 建议路由为 `/assistant/:sessionId?`。首次发送时：校验输入 → 创建会话 → 写入用户消息 → 导航至会话 URL → 消费流式响应。
- 刷新已有会话 URL 时先读取会话及历史消息，再允许继续发送；没有权限、会话不存在或已归档时返回可恢复错误页。
- 回复流式进行中禁止对同一输入重复提交，可提供停止生成；停止只中断当前响应，不删除已收到内容。
- 新消息到达且用户位于消息底部附近时自动滚动；用户正在阅读历史时不强制跳到底部，而显示“回到最新”。
- Markdown、链接和工具结果必须经过安全渲染；不执行模型返回的 HTML/脚本。

### 4.4 菜单行为

- 手机端使用从左侧滑出的抽屉，菜单按钮必须有 `aria-label`、焦点圈和至少 44×44 CSS px 点击区域。
- 选择业务功能直接导航并关闭抽屉；选择历史会话进入对应 `/assistant/{sessionId}`。
- “新建会话”只清空当前对话上下文并回到可输入状态，不清除历史会话。
- 返回仪表盘后底部输入仍存在；再次发送可以创建新会话，或按产品确认的策略继续最近会话。本分析推荐默认创建新会话，降低上下文误用风险。

## 5. 技术方案

### 5.1 分层原则

```text
手机 React UI
  -> 家加分 ASP.NET Core 同源代理（家长鉴权、输入约束、用户映射）
    -> Orbit WebApp 网关（会话、消息、SSE、交互）
      -> “家庭积分应用”稳定 agent ID/code
        -> 已授权的 family-reward MCP 子工具
```

AgentFree Studio 是智能体、技能、工具和绑定配置源；Orbit 负责实际会话、路由与流式调用。家加分只实现受约束的同源代理和产品 UI，不复制网关会话库，也不在浏览器中保存平台凭据。

### 5.2 建议后端接口

| 家加分接口 | 上游职责 | 约束 |
| --- | --- | --- |
| `GET /api/assistant/status` | 解析固定智能体及 WEBAP 路由可用性 | 只返回可用、展示名和必要能力，不返回 endpoint/密钥 |
| `GET /api/assistant/sessions?take=` | 当前用户会话列表 | `take` 限制 1–50，只返回“家庭积分应用”会话 |
| `POST /api/assistant/sessions` | 创建会话 | 服务端注入稳定 agent ID/code 和固定 webAppBotId |
| `GET /api/assistant/sessions/{id}/messages` | 读取历史消息 | 校验会话归属，支持受限分页 |
| `POST /api/assistant/chat/stream` | 发送消息并透传 SSE | 限制消息长度、会话归属、并发和超时；客户端断开时取消上游请求 |
| `PUT /api/assistant/sessions/{id}` | 改名或归档 | 只开放白名单字段，名称做长度和控制字符校验 |
| `POST /api/assistant/sessions/{id}/reset` | 重置上下文 | 明确二次确认，不删除历史记录 |
| `POST /api/assistant/interactions/{id}/respond` | 响应智能体确认/选项交互 | 校验交互属于当前会话和用户，防止越权 |

所有接口都先执行 `RequireParentProfile`。Orbit 用户标识应由当前 `AppUserProfile.AppUserId` 生成稳定、不可枚举的服务端映射；不得接受或透传前端提交的 `X-User-Name`、agent ID、endpoint、apiKey。上游 401/403/404/409/429/5xx 应转换成稳定的产品错误码，日志中记录 correlation ID，不记录完整聊天正文、token 或凭据。

### 5.3 流式协议

优先按 bigdata 已验证的 Orbit WebApp SSE/AG-UI 协议适配，不自创聊天事件格式。前端至少处理：

- 会话/轮次开始和结束；
- 文本增量与完整消息；
- 工具调用开始、结果摘要和错误；
- 需要用户确认或选择的 interaction；
- 心跳、可重试错误和终止事件。

代理必须保持 `text/event-stream`，禁止缓冲完整回复后再一次性返回。未知事件应安全忽略并记录协议版本，不能导致整个会话崩溃。

### 5.4 智能体和工具绑定

- “家庭积分应用”只是展示名，不能作为唯一运行标识。实现前必须从 AgentFree Studio/Atlas 环境确认稳定 agent ID、AgentCode/profile key、WEBAP 路由和 `webAppBotId`。
- 智能体应只绑定家加分需要的 MCP 子工具，并依当前登录家长/家庭组执行授权；任何变更积分、现金、物品、规则、家庭成员的动作都必须在工具端再次鉴权。
- 对扣分、现金、删除、家庭成员变更等高影响动作，智能体必须先返回结构化确认，用户确认后才调用写工具；不能把自然语言识别结果直接执行。
- 工具响应只返回完成回答所需摘要，避免把整个家庭数据、内部 SQL、配置或其他用户信息送入模型上下文。

## 6. 安全、隐私与可靠性

1. 麦克风只在用户点击后启用，页面离开、识别结束或取消时立即停止；本期不上传或持久化原始音频。
2. 会话列表、消息、interaction 和流式发送都必须检查当前家长的会话归属，不能只依赖不可猜测的 session ID。
3. 前后端设置消息长度、附件数量（本期为 0）、单用户并发和频率限制；429 显示可重试提示。
4. 前端刷新、网络切换或重复点击不得创建重复发送。每次发送建议使用客户端生成的 request/turn id，并由上游支持幂等或明确返回冲突。
5. 智能体回复不是业务成功证据。发生写操作时，回复必须引用 MCP 返回的实际事务/对象标识和结果；工具失败不得包装成成功。
6. 配置不可用时，仪表盘和原业务功能继续可用；底部输入区显示“智能助手暂不可用”，不能阻塞页面。
7. 聊天正文、孩子姓名和家庭数据按个人/家庭敏感信息处理，不进入普通访问日志、前端埋点或异常堆栈。
8. 若使用 Markdown，链接默认加安全属性；禁止 `dangerouslySetInnerHTML` 直出模型内容。

## 7. 验收标准

1. 已登录家长在 375×812、390×844 等手机视口打开 `/dashboard` 时，原仪表盘正常渲染，底部显示菜单与对话输入区，内容不被遮挡且无横向滚动。
2. 桌面和平板现有导航和仪表盘无回归；儿童身份及 `/watch` 不出现该入口。
3. 空输入主按钮为麦克风；语音权限仅在点击后申请，转写文本可编辑且不会自动发送；拒绝权限后文本输入仍可用。
4. 输入文本并发送后只创建一个属于当前家长、“家庭积分应用”和固定 WEBAP 路由的会话，URL 切换为对话模式并逐步显示回复。
5. 刷新对话 URL 可恢复历史；继续追问沿用同一会话。另一个家长访问该 URL 返回 403/404 产品错误，不能看到标题或消息片段。
6. 菜单可打开所有既有功能和历史会话；从对话模式返回仪表盘不删除会话，仪表盘仍保留底部输入区。
7. 网络断开、Orbit 超时、429、智能体停用和流中断均显示明确可重试状态，已输入文本或已收到回复不丢失，仪表盘仍可操作。
8. 对积分增减等写操作，智能体先展示孩子、家庭、类型、数额和描述供确认；取消不会调用写工具，确认后结果与后端真实交易记录一致。
9. 后端不会接受浏览器指定 agent ID、endpoint、apiKey 或用户身份；日志和响应不包含 token、密钥、上游堆栈或其他用户会话。
10. 键盘导航、屏幕阅读器标签、44×44 点击区域、焦点恢复、对比度、动态视口和安全区适配通过；`prefers-reduced-motion` 下不依赖大幅动画表达状态。
11. ASP.NET Core 构建、前端 lint/生产构建、代理接口自动化测试、手机视口 UI 回归、Orbit 开发环境会话闭环及写操作确认测试全部通过。

## 10. 待确认项与阻塞

1. 当前运行时未暴露 Atlas MCP 工具或资源，`list_mcp_resources` 只有 `codex_apps`，本机 `codex mcp list` 也返回 `No MCP servers configured yet`。因此无法读取 Atlas 中 REQ-033 的真实补充说明、关联缺陷/任务、项目公约、环境和功能点详情，也无法把本文、测试和完成证据写回或关闭 `TASK-050`。
2. 必须确认“家庭积分应用”的稳定 agent ID、AgentCode/profile key、WEBAP 路由和 webAppBotId。载荷只给出展示名；不得把当前任务执行智能体 `agentfree:35` 当成产品聊天智能体，也不得在代码中按展示名硬编码猜测。
3. 必须确认手机断点。本文建议仅 `sm` 以下替换底部导航；若产品要求 `lg` 以下全部使用对话输入区，需要补充平板横竖屏验收。
