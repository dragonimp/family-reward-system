# Moment 本机原件恢复与下载等待修复

## 实际问题与范围

本次核对的三条下载请求中，一张原图已于 11 月 1 日 23:37（本地 Asia/Shanghai）进入服务器缓存，但请求方的轮询在 23:30 前已停止；原提示仍笼统显示“等待原件设备传输”。另外两张未缓存原图绑定历史设备登记，当前手机只轮询当前登记的收件箱，无法自动处理这些请求。历史设备编号不同并不能证明文件不在同一部物理手机的系统相册中。

## 实现

- 打开待传输的请求消息时，以请求中的长度和 SHA-256 核对当前账号的应用原文件目录，可找回同一原件的历史或丢失索引文件；UUID 匹配不再受大小写影响。
- 自动匹配不到时，提供系统照片选择器“选择本机原文件继续分享”。只接受与请求完全一致的原文件，不建立重复照片分享。
- Linko 通过 Connect 缓存 SDK 接收并验证原件，再在事务内更新照片来源设备和仍有效的等待请求，保留请求 ID。其他成员、未登记设备、不同原文件不能恢复；正在传输或确认的请求阻止设备切换；撤销和成员权限在上传后再次核验。
- Connect C# SDK 对缓存命中的重复上传也核验请求体的长度和 SHA-256，避免把已有服务器缓存当作本次上传的原件证明。校验期间不占用缓存全局锁。
- 消息显示服务器缓存就绪与等待请求人接收的区别，并持续刷新状态。接收端连接设备期间发现缓存就绪，会切换到缓存接收。
