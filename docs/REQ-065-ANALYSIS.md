# family-reward-REQ-065 方形手表表盘需求分析

## 事项与结论

- Orbit 任务：`gpt_ce5e25fd21f04e458f84c8dd5231f455`
- 需求：`family-reward-REQ-065`（`603eb8b0-b06f-48f4-a9ee-88c47b24d634`）
- 分析任务：`family-reward-TASK-240`（`1045401e-0a77-459b-85b8-9434ea3289c1`）
- 类型：变更（手表端表盘形状与多终端适配）
- 功能点：`245414ae-7163-46af-82bb-1bb73cf9a63b`

REQ-065 要求把手表端应用表盘改为方形，并适配小天才、华为和小米系列手表。其目标、终端范围和关联功能点与 [REQ-063](./REQ-063-ANALYSIS.md)、[REQ-066](./REQ-066-ANALYSIS.md) 相同，payload 没有新增设计或验收约束。三项应合并为一项开发交付，不能按品牌复制页面，也不能重复建设三套实现。

当前 `GET /watch` 的 `.watch-shell` 已是等宽高容器，但 `.watch-face` 和 `.watch-face:before` 仍使用 `border-radius:50%`，所以表盘实际为圆形。`TASK-240` 可凭本文、项目日志和提交关闭；REQ-065 尚未实现。项目管理侧应选择 REQ-063、REQ-065、REQ-066 中一个作为主需求，其余标记为重复并关联到主需求；“重复关闭”不代表方形表盘已经交付。

## 统一产品口径

1. “方形”指应用表盘主容器、内描边和主题裁剪区域为直角方形；圆形积分环是内容组件，可保留。
2. 所有品牌使用同一套响应式 `/watch` 页面，以视口能力和安全区适配，不使用 User-Agent 或品牌判断分叉 UI，也不复制厂商商标和系统界面。
3. 保留现有设备绑定、积分、规则、申请、好友、排行榜、表盘设置和 VIP 权益；不修改 API、数据库、主题目录和付费模型。
4. 以可用宽高的最小边决定 1:1 容器；现代 WebView 可使用 `min()`、`clamp()`、`dvh`、`aspect-ratio` 增强，旧 WebView 必须继续获得确定的 `width`/`height` 回退。
5. 菜单和主要操作必须完全位于方形安全区内，不依赖圆形外框外侧的负偏移；系统圆角、状态栏或表冠区域不能遮挡操作。

## 实施范围

| 层级 | 必须修改 | 明确不改 |
| --- | --- | --- |
| `/watch` CSS | 表盘外框、内描边和主题裁剪改为方形；调整安全区、菜单锚点及窄屏规则 | 主题配色、VIP 动画语义和减少动态效果降级 |
| `/watch` HTML/JS | 仅在布局或可访问性验证需要时最小调整 | 面板状态机、设备绑定和表盘保存流程 |
| API/数据 | 无 | `GET/PUT /api/watch/settings`、积分/奖励逻辑、VIP 服务端校验 |
| 原生壳/发布 | 本需求不直接修改 | 包名、签名、市场材料和受控部署流程 |

实施至少满足：

- `.watch-face` 和 `.watch-face:before` 不再使用 `border-radius:50%`，免费/VIP 主题共用同一个方形裁剪边界。
- `.watch-shell` 保持 1:1；不支持现代 CSS 的 Android 7.1.1/8.1.0 WebView 仍能得到稳定等宽高布局。
- 表单、列表、儿童姓名和规则长文本不产生横向滚动；高度不足时业务面板可纵向滚动。
- 菜单按钮完整位于容器内，点击目标不低于当前约 `34px` 的下限。
- 增加静态回归，断言方形样式、兼容回退和窄屏规则存在；静态测试不替代真机验收。

## 验收标准

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| TC-065-01 | 方形外观 | 所有免费/VIP 主题的主容器、内描边和裁剪边界为方形，无圆形外框 |
| TC-065-02 | 基础流程 | 未绑定、首页、菜单、积分申请、规则、好友、排行榜、设备和表盘设置均可读、可点击、可滚动 |
| TC-065-03 | 视口覆盖 | 至少覆盖 240×240、320×320、320×360、390×390 和高度受限视口，无横向溢出或关键内容裁切 |
| TC-065-04 | 小天才 | Android 7.1.1/8.1.0 目标定制 WebView 或等效环境中加载、滚动、输入、主题切换正常 |
| TC-065-05 | 华为 | 至少一台明确型号/系统的目标设备或等效环境中，安全区、系统圆角和方向变化不遮挡主要操作 |
| TC-065-06 | 小米 | 至少一台明确型号/系统的目标设备或等效环境中，长文本、列表、输入和主题切换正常 |
| TC-065-07 | 可访问性 | 大字体、`safe-area-inset` 和减少动态效果设置下仍可操作，VIP 装饰动画按既有规则停止 |
| TC-065-08 | 业务回归 | 表盘保存/重载一致；非 VIP 不能保存 VIP 表盘；积分、奖励和绑定数据不因外形变化 |

“适配各类手表端”的最低关闭证据，是小天才、华为、小米各至少一台已登记型号的真机记录，或能证明 WebView、视口和安全区等价的受控环境记录。桌面浏览器模拟只能作为布局预检。

## 风险与待确认项

- 仓库目前只对小天才 Android 7.1.1/8.1.0、320×360 开放机型记录了较清晰的首版边界；华为、小米需在开发验收前补充型号、系统、WebView/入口容器和安全区矩阵。
- 小天才 D3 为 Android 4.4/API 19，低于当前 `minSdk=23`。240×240 可用于布局压力测试，但不能据此宣称 D3 真机兼容。
- 旧 WebView 对 `dvh`、`min()`、`clamp()` 和 `aspect-ratio` 支持不一致，不能删除现有基础 `calc()` 宽高回退。
- 若产品仍需支持圆屏，必须另行定义圆屏识别、外观降级和验收设备；当前需求文字按所有支持端统一显示方形解释。
- REQ-063、REQ-065、REQ-066 的主从关系需由项目管理侧确认；在确认前也只应建立一个实现任务，并让一次验收证据同时关联三项。
