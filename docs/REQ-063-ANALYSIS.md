| 多终端布局 | 在小天才、华为、小米的方形或近方形 WebView，以及不同分辨率、刘海/圆角安全区中，内容不溢出、不被裁切。 |

## 现状与设计决策

`FamilyReward.Api/Program.cs` 的 `GET /watch` 内联了页面样式和脚本。它已用 `100dvh`、`vmin`、`clamp()`、`env(safe-area-inset-*)` 和 `prefers-reduced-motion` 为受限 WebView 降级；应在同一入口完成本项变更，避免按品牌分叉页面。

采用“统一方形、能力检测优先”的适配策略：

1. `.watch-shell` 保持基于可用宽高的最小边计算，显式补充 `aspect-ratio: 1 / 1` 作为现代 WebView 的布局约束；旧 WebView 继续使用已有等宽高声明。
2. `.watch-face` 和 `:before` 的圆角改为 `0`；不要用大圆角模拟特定品牌，以免在方形屏上损失可用面积。主题背景和 VIP 装饰层仍以容器裁剪。
3. `.screen` 使用与安全区和边框相协调的 `clamp()` 内边距；内容宽度从现有 `70vmin`/固定上限收敛到容器可用宽度，确保长儿童姓名和表单不会横向滚动。
4. 右侧菜单浮钮不得依赖圆形表盘外侧的负偏移。在方形容器内定位，点击目标保持至少约 `34px`，避免被窄屏或系统圆角裁掉。
5. 积分环是内容组件而非表盘轮廓，可以保留圆形，以维持积分视觉焦点；若最小设备实测空间不足，再单独评估将其改为圆角方块，不能在本需求中无证据地改变语义。

这套方式借鉴小天才、华为、小米手表常见的方形/近方形可用区域，而不假定它们使用同一个操作系统、分辨率、WebView 版本或硬件表冠位置。

## 风险、依赖与待确认项

1. 当前仓库仅明确维护小天才 Android 7.1.1/8.1.0 WebView 发布路径；华为与小米的目标型号、系统、入口容器和最小 WebView 版本尚未提供。实施前需补充测试设备矩阵，实施后需取得对应证据。
2. 部分旧 WebView 对 `dvh`、`min()`、`clamp()` 或 `aspect-ratio` 支持不一致。现有非 `@supports` 等宽高回退必须保留；必要时为旧内核增加简单的 `width/height` 回退，不能只依赖新 CSS。
3. 设备可能有圆角屏幕和状态栏/表冠遮挡。安全区变量为零时仍需保留保守内边距，且菜单不允许放到容器外。
4. 产品没有定义圆形设备的保留策略。本分析按“所有支持的手表端统一方形表盘”解释；若仍须支持圆屏，应在开发前新增明确的圆屏降级规格和设备识别规则。
