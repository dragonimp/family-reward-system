| 用例 | 需求行为 | 静态检查点 | 自动化用例名称 |

## TC-031：缺项计算

前置条件：使用 `xiaotiancaiReleaseMaterials` 默认材料清单，不读取浏览器或生产数据。

步骤与预期：

1. 用空状态表计算准备度，预期总数 24、已准备 3、未完成 21、凭证已配置 0、完成度 13%。
2. 将开发者准入和联系人标记为 `credential_configured`，预期已准备仍为 3、未完成仍为 21，同时凭证已配置为 2。
3. 将同两项标记为 `verified`，预期已准备为 5、未完成为 19、完成度为 21%。

## TC-032：凭证安全引用

前置条件：读取上架准备页源码，不访问或输出用户中心的真实凭证。

步骤与预期：

1. 检查页面指向“用户中心 → 个人信息管理 → 凭证管理”。
2. 检查页面明确不接收密码、验证码、证件号码或密钥原文，并说明“已配置”不等于“已验证”。
3. 检查短信验证码和一次性儿童认证码仅在送审时人工输入。
4. 检查页面不存在 `input` 或 `textarea`，防止把敏感原文写入此工作区；页面只保存材料状态枚举。

## TC-033：完整工作区与材料覆盖

前置条件：读取前端路由、导航、页面和材料清单源码。

步骤与预期：

1. 检查 `/watch-release` 路由和“上架准备”导航存在。
2. 检查材料总数为 24、ID 无重复，覆盖账号与主体、合规材料、构建与签名、真机与素材、审核与送审五组。
3. 检查开发者准入、发布主体、软著、备案、正式签名 APK、图标、介绍图、真机测试、审核账号和一次性认证码等关键项存在。
4. 检查页面明确：只有真实签名包、合规材料、主体证照、真机结果、截图和平台受理证据核验完成，才能送审或关闭真实上架事项。
