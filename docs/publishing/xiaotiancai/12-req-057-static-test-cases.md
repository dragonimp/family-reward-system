## TC-057-01：材料清单与文件一致性

前置条件：检出待登记材料对应的仓库提交，不访问生产项目管理系统。

步骤与预期：

1. 读取 `release-metadata.json`，预期应用名为“家加分手表积分”、包名为 `net.impx.happylife.watch`、版本为 `1.0.0 (100)`。
2. 检查元数据引用的 APK、公开签名证书、图标、5 张介绍图和 6 份 PDF 均存在；预期无缺失或同名冲突。
3. 重新计算 APK 和 `files` 数组中各文件的 SHA-256，并从 PEM 解析 X.509 证书 SHA-256 指纹；预期分别与元数据中的文件哈希和证书指纹一致。
4. 检查 `externalEvidenceStillRequired`；预期软著、APP 备案、盖章/签署文件、平台回执和物理真机证据仍明确列为外部缺项。

## TC-057-02：上架记录归属正确

前置条件：测试账号具有 `family-reward` 项目“应用上架”栏目的读写权限，接口使用非生产测试数据或经批准的目标记录。

步骤与预期：

1. 按项目 `family-reward`、应用 `family-points`、平台 `xiaotiancai`、版本 `1.0.0 (100)` 查询记录。
2. 记录不存在时通过应用接口创建草稿；存在时复用原记录。
3. 回读记录，预期项目、应用、平台、版本和包名全部正确，且相同自然键只对应一个上架记录 ID。

## TC-057-03：逐项登记并保持真实状态

前置条件：`TC-057-01` 通过，且已取得 `TC-057-02` 的上架记录 ID。

步骤与预期：

1. 分别登记 APK、公开签名证书、图标、5 张介绍图、隐私政策、用户协议、客服审核说明和服务器性能报告；预期状态为 `ready`，每项均有独立资产记录或介绍图资产组。
2. 登记待真机验证的测试报告和待盖章免责函；预期状态为 `draft`，不得自动转为 `ready`。
3. 登记软著、APP 备案、法人证件和真机矩阵缺项；预期状态为 `missing` 或 `external_action_required`，并保留缺项原因。
4. 回读材料统计；预期已完成、草稿和缺项数量与逐项状态一致，缺项不阻止已完成材料保存。

## TC-057-04：幂等上传与材料版本化

前置条件：至少一个材料已登记，测试环境允许重复调用。

步骤与预期：

1. 使用相同材料键和 SHA-256 重复执行登记；预期复用原资产，不新增重复版本或重复文件。
2. 使用相同材料键、不同 SHA-256 上传修订文件；预期创建新资产版本，当前引用指向新版本，旧版本及审计记录仍可查询。
3. 再次执行整批登记；预期上架记录 ID 不变，每个材料键只有一个当前版本。

## TC-057-05：接口回读与审计证据

前置条件：完成一轮材料登记。

步骤与预期：

1. 通过正式应用接口重新读取上架记录和材料列表。
2. 预期回执包含上架记录 ID，以及每项材料的资产 ID、SHA-256、状态、上传时间和操作者审计标识。
3. 预期文件哈希能对应 `release-metadata.json`，状态能对应 `TC-057-03`；脱敏后把回执附到 Orbit/Atlas 事项证据。
4. 仅有仓库路径、Git 提交、ZIP 或 SQL 草案而没有接口回执时，本用例判定失败。

## TC-057-06：敏感信息与接口边界

前置条件：准备包含公开证书和敏感凭证名称的测试输入，不使用真实秘密值。

步骤与预期：

1. 上传公开 PEM 证书，预期接口允许登记证书指纹。
2. 尝试提交 JKS、keystore 密码、测试账号密码、完整身份证号或一次性验证码字段，预期客户端或接口拒绝，日志和响应不回显值。
3. 检查执行路径，预期只调用项目管理应用接口，不直接执行 Atlas 数据库 SQL，不触发部署、发布、提审或生产服务操作。

## TC-057-07：关闭条件

前置条件：收集本组其余用例的执行结果。

步骤与预期：

1. 若 `TC-057-01` 通过但接口用例未执行，预期 TASK-215 可凭测试设计文档关闭，REQ-057 保持待实现或等待接口能力/授权。
2. 若 `TC-057-02` 至 `TC-057-06` 通过，且已提供上架记录 ID、资产 ID、哈希、状态、幂等结果和审计回执，预期 REQ-057 具备关闭证据。
3. 任一材料被虚假标为完成、出现重复资产、缺少回读证据或发生数据库直写时，预期 REQ-057 不可关闭。
