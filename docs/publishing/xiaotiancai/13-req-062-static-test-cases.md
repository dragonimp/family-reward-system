## TC-062-01：五款 VIP 表盘动画覆盖

前置条件：检出包含 REQ-062 实现的提交，读取 `/watch` 页面源码。

步骤与预期：

1. 检查 `meteor`、`snow`、`flowers`、`night`、`pixel` 五款 VIP 表盘；预期每款均有独立的 `:after` 动画层和对应动画声明。
2. 检查流星、雪花、花朵、星夜和像素效果；预期动画节奏或运动方式可区分，且不依赖远程图片、字体或脚本。
3. 执行 `frontend/requirements.test.ts` 中 `REQ-062 keeps VIP watch-face animation decorative and accessible`；预期断言通过。

## TC-062-02：VIP/非 VIP 权益隔离

前置条件：准备一个具有 `vip_watch_faces` 权益的家庭和一个无该权益的家庭，各绑定一台测试手表。

步骤与预期：

1. VIP 手表进入表盘设置；预期五款 VIP 表盘可选，免费表盘仍可选，页面不改变积分、时间和已有功能。
2. 非 VIP 手表进入表盘设置；预期五款 VIP 选项禁用并提示“需要 VIP家庭+ 套餐”，免费表盘保持可用。
3. 非 VIP 客户端绕过按钮直接向 `PUT /api/watch/settings` 提交 VIP 表盘代码；预期服务端拒绝或回退到已授权表盘，不能仅依赖前端禁用。
4. 切换家庭、孩子或设备令牌重复检查；预期权益不跨家庭、孩子或设备泄漏。

## TC-062-03：表盘切换状态

前置条件：VIP 手表当前使用一款免费表盘。

步骤与预期：

1. 依次切换五款 VIP 表盘；预期选中态、主表盘背景和动画立即对应目标款式，旧动画不残留或叠加。
2. 在 VIP 与免费表盘之间往返切换；预期免费表盘不会出现 VIP 动画层的可见效果。
3. 刷新页面或重启 WebView；预期服务端保存的表盘恢复正确，同一时刻只运行当前表盘对应的动画。
4. 快速连续点击不同表盘；预期最终状态与最后一次成功响应一致，无界面卡死、重复提示或错误持久化。

## TC-062-04：积分与时间刷新可读性

前置条件：选择任一 VIP 表盘，准备可触发积分变化的测试数据。

步骤与预期：

1. 观察时间和积分区域至少一个刷新周期；预期文字始终位于动画层之上，无闪烁、重影或被装饰遮盖。
2. 通过正常业务流程增加和扣减积分后刷新手表；预期新积分正确显示，当前表盘及动画保持稳定。
3. 积分为 0、较大值、负值（若业务允许）以及时间文本变化时检查布局；预期不截断核心信息、不改变积分计算结果。
4. 进入菜单或表单再返回首页；预期业务内容正常，动画不影响导航或输入状态。

## TC-062-05：窄屏和旋转布局

前置条件：在等效 WebView 中准备 240×240、320×360、360×360、390×450、368×194 代表性视口。

步骤与预期：

1. 每个视口分别打开五款 VIP 表盘；预期主时间、积分、品牌和菜单入口位于安全区内，无横向滚动。
2. 在 368×194 横屏检查最小高度布局；预期动画不扩大文档尺寸，核心按钮可见且可点击。
3. 在支持旋转的设备切换横竖屏；预期重排后仅当前表盘动画可见，不出现裁切外泄或布局跳动。

## TC-062-06：减少动态效果降级

前置条件：系统或开发工具可切换 `prefers-reduced-motion: reduce`。

步骤与预期：

1. 启用减少动态效果并重新打开五款 VIP 表盘；预期装饰层保留静态背景，但所有 VIP 动画为 `none`。
2. 在启用状态下切换表盘、刷新积分和重新载入；预期不会重新启动动画，信息和操作仍完整。
3. 关闭减少动态效果并重新载入；预期动画恢复，业务数据不因偏好切换而变化。

## TC-062-07：弱网与资源失败回退

前置条件：使用网络限速/离线模式，并可阻断非必要静态资源请求。

步骤与预期：

1. 页面首次加载后切换到弱网；预期 CSS 内建动画继续或静态背景保持，无破图和未捕获异常。
2. 阻断图片、字体等非必要资源；预期五款表盘仍有本地渐变/图形回退，时间、积分和菜单可读可用。
3. 令设置读取或保存请求超时；预期保留最近确认状态或给出错误提示，不把未确认的表盘当作已保存，不影响其他业务请求。

## TC-062-08：动画层不拦截操作

前置条件：打开任一 VIP 表盘并进入可操作页面。

步骤与预期：

1. 检查装饰伪元素；预期设置 `pointer-events: none`，业务内容具有更高层级。
2. 点击菜单、规则、输入及返回控件；预期命中目标控件，无点击被吞、焦点丢失或误触。
3. 使用键盘或辅助技术遍历页面；预期动画层不进入焦点顺序，也不产生额外朗读内容。

## TC-062-09：无业务写入副作用

前置条件：记录测试家庭的积分流水、奖励规则、订阅状态和当前表盘，开启 API 请求日志或浏览器网络面板。

步骤与预期：

1. 仅浏览五款 VIP 表盘并等待多个动画周期；预期不产生积分、交易、规则或订阅写请求。
2. 切换表盘；预期最多发生表盘设置读取/保存请求，不调用积分、交易、规则或订阅变更接口。
3. 刷新积分、切换视图和重新载入页面后比对数据；预期积分流水、奖励规则和订阅状态与前置记录一致，仅经用户确认的表盘设置允许变化。
