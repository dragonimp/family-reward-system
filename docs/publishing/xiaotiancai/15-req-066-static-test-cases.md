## TC-066-01：统一方形外观与兼容回退

前置条件：检出 REQ-066 实现，读取 `GET /watch` 页面源码。

1. 检查 `.watch-face` 和 `.watch-face:before`；预期均为 `border-radius:0`，无 `border-radius:50%`。
2. 检查 `.watch-shell`；预期基础 `vw`、`vmin` 等宽高回退和 `aspect-ratio:1 / 1` 能力增强并存。
3. 检查 `max-width:260px`/`max-height:260px` 窄视口规则。
4. 检查 `.menu-dock` 位于右上安全区、无负右偏移及外移变换。
5. 执行自动化 `REQ-066 uses one responsive square watch face with an internal safe menu`；预期通过。

## TC-066-02：基础流程与面板

前置条件：准备未绑定设备和具有积分、规则、好友及申请数据的已绑定设备。

1. 未绑定设备打开 `/watch`；预期认证码输入、提交和错误提示完整可见。
2. 已绑定设备依次进入首页、菜单、积分申请/详情、规则、好友、排行榜、设备和表盘设置；预期可进入、返回、滚动和操作。
3. 使用长儿童姓名、长规则名和多行申请内容；预期核心文本可读、输入框不超出表盘、无横向滚动。
4. 开关菜单；预期按钮完整可见可点击，不与系统边缘或主要内容重叠。

## TC-066-03：尺寸与方向覆盖

前置条件：准备 240×240、320×320、320×360、390×390 和至少一个高度低于宽度的受限视口。

1. 各视口检查未绑定页、首页、菜单、积分申请及表盘设置；预期表盘保持 1:1、无页面级横向溢出或主要操作裁切。
2. 240×240 下预期窄屏规则生效、菜单仍在容器内；该结果不得表述为小天才 D3 真机兼容证明。
3. 切换横竖方向；预期按可用短边重排，主题与 VIP 装饰不扩大文档尺寸。
4. 记录 viewport、WebView/浏览器版本、横纵向溢出量和关键截图。

## TC-066-04：小天才系列

前置条件：记录明确目标型号、Android、定制 WebView、屏幕和入口容器；最低覆盖 Android 7.1.1/8.1.0 路径或等效环境。

1. 冷启动及重载；预期旧 WebView 可使用基础 `calc(100vw - 52px)` 回退，不因现代 CSS 缺失而塌陷。
2. 完成绑定、滚动、输入申请和返回；预期无语法错误、触控失效或关键裁切。
3. 切换免费与已授权 VIP 主题并重载；预期方形边界一致、保存状态正确恢复。
4. 保存型号、系统、WebView、截图/录屏和设备日志；信息不完整时不得泛化为系列通过。

## TC-066-05：华为系列

前置条件：记录至少一台目标华为手表的型号、系统、WebView/容器、分辨率、系统圆角和安全区。

1. 打开首页和菜单；预期状态栏、圆角和安全区不遮挡时间、积分或菜单。
2. 在积分申请、规则和表盘设置完成滚动与输入；预期焦点、软键盘、返回正常。
3. 若支持方向变化，切换后复测；预期按短边适配，无负偏移或不可点击区。
4. 保存设备矩阵及视觉/交互证据；桌面模拟不能单独作为通过证据。

## TC-066-06：小米系列

前置条件：记录至少一台目标小米手表的型号、系统、WebView/容器、分辨率和安全区。

1. 用长姓名、长规则及多条列表数据检查首页、规则、好友和排行榜；预期文本按规则处理、列表可滚动、无横向溢出。
2. 输入并提交多行积分申请；预期软键盘、焦点、按钮和错误提示可用。
3. 切换免费与已授权 VIP 主题并重载；预期方形裁剪一致、设置恢复正确。
4. 保存设备矩阵及视觉/交互证据；桌面模拟不能单独作为通过证据。

## TC-066-07：可访问性降级

1. 启用非零 `safe-area-inset-*`；预期内容、菜单和表单仍在可操作区域。
2. 将字体调到目标设备最大档；预期核心数据和按钮可读可达、无横向滚动。
3. 启用 `prefers-reduced-motion: reduce`；预期 VIP 装饰动画停止，时间、积分及操作正常。
4. 触控和辅助技术遍历关键操作；预期装饰层不拦截点击、不进入焦点顺序。

## TC-066-08：设置权限与业务无副作用

前置条件：准备 VIP/非 VIP 家庭，记录表盘、积分流水、奖励规则、绑定及订阅状态。

1. VIP 用户切换并重载；预期设置读写一致，方形改造不改变接口契约。
2. 非 VIP 经界面及直接请求保存 VIP 表盘；预期仍被服务端拒绝或按既有规则回退。
3. 浏览主题和面板并等待动画；预期不产生积分、交易、规则、绑定或订阅写请求。
4. 正常提交积分申请并比对数据；预期仅业务动作改变积分/流水，表盘、绑定和权限正确。
