# 家族族谱首版

## 定位与范围

族谱是独立的家族成员与亲属关系空间，不等同于用于共享孩子积分的家庭圈子，也不从已有家庭成员备注、孩子档案或圈子自动导入任何人。一个用户可加入多个族谱；一个族谱可包含尚未注册的长辈和亲属。网页入口为「管理 → 家族族谱」，iPhone / iPad 原生入口为「家庭 → 家族族谱」，使用用户中心登录身份。

## 使用流程

1. 已登录的家长角色用户创建族谱，填写名称、可选姓氏和简介。创建人是管理员，并在族谱中生成一条与本人账号关联的人物记录。
2. 其他用户通过名称或姓氏查找族谱。搜索结果只展示族谱名称和姓氏，不展示人物名单、人数、简介或关系。
3. 用户填写本人姓名和可选说明提交加入申请，可在页面查看等待审核、已通过或未通过状态。管理员审核时同时看到用户中心账号名称，并可选择关联族谱中尚未绑定账号的人物；若不选择，则生成新的人物记录。未通过的申请不授予任何读取权限。
4. 已加入成员按姓名或支系搜索人物，查看辈分、支系、备注及父母、子女、配偶关系。管理员从具体人物资料页添加该人物的父母、子女或配偶，也可补录、编辑人物及移除关系。
5. 管理员可在尚未关联账号的人物资料页生成专属邀请链接。受邀者使用用户中心账号登录，核对族谱和人物后确认；服务端在同一事务中授予成员身份、认领该人物并消耗邀请。链接 7 天有效、仅可使用一次；重新生成会撤销此人物之前的链接。已认领其他人物的账号不能再次认领。
6. 人物资料页根据已记录的父母关系自动展示兄弟姐妹、祖辈、孙辈、父母的兄弟姐妹、兄弟姐妹的子女和堂表亲。至少共享一位父母即推导为兄弟姐妹；推导结果按人物去重，只显示最直接的一种间接关系。删改基础关系后重新计算，不保存额外关系边。

## 权限与数据边界

- 未加入者只可搜索族谱名称/姓氏并申请加入。所有人物、关系、简介及申请内容均要求当前账号为该族谱成员。
- 只有管理员可审核申请、编辑人物及关系。前端控制之外，所有读取与写入接口均在服务端以用户中心身份和 `genealogy_tree_users` 复核权限；客户端身份头不能覆盖当前用户。
- 人物记录与登录账号分开保存。未注册亲属由管理员补录；审核通过时由管理员决定关联已有未认领人物，或新建本人记录。系统不会仅凭同名自动合并。
- 邀请令牌仅通过生成响应返回，数据库只存 SHA-256 摘要。链接本身相当于访问凭证，应只发给该人物本人；接受页需要登录且明确确认绑定。
- 父母关系有方向（父母 → 子女），配偶关系无方向。服务端拒绝跨族谱关联、自关联、重复关系和祖先循环。
- 推导关系仅依据同族谱的明确父母边，不凭同名、姓氏、支系或配偶关系猜测血缘。未收集性别和年龄，因此不区分哥哥、姐姐、弟弟、妹妹，也不细分父系/母系及长幼。
- 首版不收集精确生日、住址、联系方式；备注限 500 字。族谱名称和姓氏可被搜索，因此不要写入不愿公开的信息。

## 接口与容量

`/api/genealogies` 提供本人族谱的查询和创建；`/discover?q=` 只搜索公开的名称/姓氏；`/my-join-requests` 提供本人申请状态；`/{id}/join-requests` 提供申请和管理员审核；`/{id}/people` 与 `/{id}/relationships` 提供成员查询及关系维护；`/{id}/people/{personId}/inferred-relationships` 在成员权限下实时计算该人物的间接关系。人物搜索一次最多返回 100 条，并报告是否有更多结果；输入姓名或支系可继续缩小范围。基础关系列表首版最多返回 2000 条，超出时需引入分页。

## 部署与验收

数据库结构位于独立的一次性迁移 `scripts/migrations/20261008-genealogy-v1.sql` 和 `scripts/migrations/20261009-genealogy-person-invitations-v1.sql`。部署前应备份并运行现有 `scripts/run-db-migrations.sh`；应用启动不会创建、修补或导入族谱数据。部署顺序为备份 → 迁移 → API/Web 发布 → 实际账号验收。上线验收增加：邀请过期、重复使用、重新生成撤销旧链接、已绑定人物和已认领其他人物账号拒绝、受邀账号确认后读到正确人物。实际双账号流程需用两个真实用户验证。

当前实现包含网页、API 与原生 iOS。复杂图形树布局、导出和已故成员标记留待后续版本。
