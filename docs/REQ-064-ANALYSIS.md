# family-reward-REQ-064 方形手表表盘需求分析

## 事项与结论

- Orbit 任务：`gpt_4b051ff7eaab47d491caea199bd8de7f`
- 需求：`family-reward-REQ-064`（`a717db5d-3d92-4762-b529-d8ffb207ac2a`）
- 分析任务：`family-reward-TASK-241`（`4031b26c-0cc9-4962-a57a-3419fb2f91b4`）
- 类型：变更（手表端表盘形状与多终端适配）
- 功能点：`245414ae-7163-46af-82bb-1bb73cf9a63b`

REQ-064 要求把手表端应用表盘改为方形，并适配小天才、华为和小米系列手表。其目标、终端范围及功能点与 [REQ-063](./REQ-063-ANALYSIS.md)、[REQ-065](./REQ-065-ANALYSIS.md)、[REQ-066](./REQ-066-ANALYSIS.md) 相同，payload 没有新增产品或验收约束。四项应合并为一次开发与验收，不应按需求编号或品牌复制实现。

当前 `GET /watch` 中 `.watch-shell` 已是等宽高容器，但 `.watch-face` 与 `.watch-face:before` 仍使用 `border-radius:50%`，所以实际外框和裁剪区域仍为圆形。`TASK-241` 可凭本文和对应提交关闭；REQ-064 尚未实现。项目管理侧可将 REQ-063 至 REQ-066 中一项定为主需求，其余作为重复项关联关闭，但“重复关闭”不代表方形表盘已经交付。

## 统一产品口径

1. “方形”指应用表盘主容器、内描边和主题裁剪区域为直角方形；圆形积分环属于内容组件，可保留。
2. 小天才、华为、小米共用一套响应式 `/watch` 页面，根据视口能力和安全区适配，不依赖 User-Agent 或品牌分叉，也不仿制厂商商标和系统界面。
3. 保留现有设备绑定、积分、规则、申请、好友、排行榜、表盘选择及 VIP 权益；本需求不修改 API、数据库、主题目录或付费模型。
4. 以可用宽高最小边确定 1:1 容器。现代 WebView 可用 `min()`、`clamp()`、`dvh` 和 `aspect-ratio` 增强，旧 WebView 必须继续获得明确的 `width`/`height` 回退。
5. 菜单与主要操作必须完整位于方形安全区内，不再依赖圆形表盘外侧的负偏移；系统圆角、状态栏或表冠区域不得遮挡操作。

## 实施范围

| 层级 | 必须修改 | 明确不改 |
| --- | --- | --- |
| `/watch` CSS | 表盘外框、内描边和主题裁剪改为方形；调整安全区、菜单锚点及窄屏规则 | 主题配色、VIP 动画语义和减少动态效果降级 |
| `/watch` HTML/JS | 仅在布局或可访问性验证需要时最小调整 | 面板状态机、设备绑定和表盘持久化流程 |
| API/数据 | 无 | `GET/PUT /api/watch/settings`、积分/奖励逻辑及 VIP 服务端校验 |
| 原生壳/发布 | 本需求不直接修改 | 包名、签名、市场材料和受控部署流程 |

实施至少满足：

- `.watch-face` 和 `.watch-face:before` 不再使用 `border-radius:50%`，所有免费/VIP 主题共用方形裁剪边界。
- `.watch-shell` 保持 1:1；不支持现代 CSS 的 Android 7.1.1/8.1.0 WebView 仍有稳定的等宽高布局。
- 表单、列表、儿童姓名和规则长文本不产生横向滚动；高度不足时业务面板可纵向滚动。
- 菜单按钮完全位于容器内，点击目标不低于当前约 `34px` 的下限。
- 增加静态回归，断言方形规则、旧 WebView 回退和窄屏规则存在；静态检查不能替代目标设备视觉验收。

## 验收标准

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| TC-064-01 | 方形外观 | 所有免费/VIP 主题的主容器、内描边和裁剪边界为方形，无圆形外框 |
| TC-064-02 | 基础流程 | 未绑定、首页、菜单、积分申请、规则、好友、排行榜、设备和表盘设置均可读、可点击、可滚动 |
| TC-064-03 | 视口覆盖 | 至少覆盖 240×240、320×320、320×360、390×390 及高度受限视口，无横向溢出或关键内容裁切 |
| TC-064-04 | 小天才 | Android 7.1.1/8.1.0 目标定制 WebView 或等效环境中加载、滚动、输入和主题切换正常 |
| TC-064-05 | 华为 | 至少一台明确型号/系统的目标设备或等效环境中，安全区、系统圆角和方向变化不遮挡主要操作 |
| TC-064-06 | 小米 | 至少一台明确型号/系统的目标设备或等效环境中，长文本、列表、输入和主题切换正常 |
| TC-064-07 | 可访问性 | 大字体、`safe-area-inset` 和减少动态效果设置下仍可操作，VIP 装饰动画按既有规则停止 |
| TC-064-08 | 业务回归 | 表盘保存/重载一致；非 VIP 不能保存 VIP 表盘；积分、奖励和绑定数据不因外形变化 |

“适配各类手表端”的最低关闭证据，是小天才、华为、小米各至少一台已登记型号的真机记录，或能证明 WebView、视口和安全区等价的受控环境记录。桌面浏览器模拟只能作为布局预检。

## 风险与待确认项

- 仓库目前仅对小天才 Android 7.1.1/8.1.0、320×360 开放机型记录了较清晰的首版边界；华为、小米需在开发验收前补充型号、系统、WebView/入口容器和安全区矩阵。
- 小天才 D3 为 Android 4.4/API 19，低于当前 `minSdk=23`。240×240 可作为布局压力测试，但不能据此宣称 D3 真机兼容。
- 旧 WebView 对 `dvh`、`min()`、`clamp()` 和 `aspect-ratio` 支持不一致，不得删除现有基础 `calc()` 等宽高回退。
- 若产品仍需支持圆屏，必须另行定义圆屏识别、外观降级和验收设备；当前需求文字按所有支持端统一显示方形解释。
- REQ-063 至 REQ-066 的主从关系需由项目管理侧确认；确认前也只应建立一个实现任务，并让同一组验收证据关联四项需求。
