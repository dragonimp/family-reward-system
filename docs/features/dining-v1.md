# 干饭 V1

菜单顺序：干饭、成长、活动、运动、我的。默认打开干饭；活动深链仍进入活动。

首页沿用产品文案：今天吃啥？／别纠结了，这顿我安排！／🎲 帮我决定。可不选心情；点击后申请前台定位、查询真实餐厅、显示盲盒动画与一个结果。提供就吃这家、换一家、导航和收藏；右上角提供记录与生活圈。不会因为新菜单要求用户先建立家庭或成为家长。

## 数据与边界

- iOS 使用 Apple MapKit `MKLocalSearch.Request` 的餐厅 POI 搜索；候选限制在搜索中心约 3 公里内。使用公开上海市中心坐标进行了真实搜索验证，返回 25 家真实餐厅。具体用户位置、设备权限与真实安装后的交互仍需独立验收。
- iOS 显示坐标计算的直线估算距离；Apple 步行路线成功后替换为路线距离和预计时间。MapKit 未提供可靠价格或评分时不显示虚构值。省钱模式在价格缺失时优先就近；吃好模式保留收藏和确认吃过的选择，但不宣称知道消费水平。
- Android 通过已认证的 `POST /api/dining/nearby` 调用高德。使用 `Dining__AmapWebServiceKey` 注入仅服务端的 Web 服务 Key；不在客户端或源代码保存。服务器先用高德正式接口将 GPS/WGS84 转换成 GCJ-02，再查询餐饮 POI。导航明确使用高德 GCJ-02，不直接将它传给其他坐标系的导航器。
- 当前运行服务没有此 Key。缺少配置返回明确 503；网络、配额或供应商失败返回 502；不使用演示餐厅或静默切换地图供应商。高德真实环境验收和该 API 的正式部署仍待完成。
- 位置通过请求体发送，响应禁止缓存；地图 Key 所在的出站 URI 禁止 HTTP 客户端日志。仅主动点击定位或保存生活圈时读取位置，不在后台追踪。
- 选择、吃过确认、换店反馈、收藏及家／公司生活圈使用本机独立账号归档。GUID 账号先按类型规范化，其他业务标识保留原大小写。历史显示设备当地时间；记录时间持久化为 UTC/ISO 8601。最多展示最近 300 条，习惯累计计数保留。
- 选择记录与“吃过了”分开；后者幂等，反复点击不会重复增加。文件写入成功后才改变内存状态；失败保留原记录并提示。
- 推荐有正的熟悉度权重；常吃餐厅一直有机会。换一家只避开当前店；只有一家时明确提示。新鲜模式偏向本机记录里未选过的店；辣味只使用店名／菜系线索，提示向店家确认。
- 本版不做好友／群组分享、小队、AA 或支付，不引入模型直连，不另建认证体系。记录当前不跨设备同步。

## 验证

`tests/Dining` 覆盖推荐权重、重抽、空结果、坐标与供应商数据校验、认证隔离、Key 缺失、错误响应、坐标转换和 Key 不回传。`DiningModelTests.swift` 覆盖原生模型、GUID 账号、历史与累计习惯、持久化及失败保留。`DiningMapSearchCheck.swift` 使用真实 Apple 地图与公开测试坐标，不依赖用户位置或模拟餐厅。
