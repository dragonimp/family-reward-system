# 安卓运动模块对齐 iOS（2026-11-09）

## 范围及基准

对照当前 iOS `parent-app/ios/HappyLifeParent/ExerciseView.swift` 的实际实现，增量调整安卓。iOS 与后端未修改，不新增数据库、不迁移或覆盖用户历史数据。

| 区域 | 安卓调整后的行为 |
| --- | --- |
| 关联活动 | 置于最前，显示活动名；开始前可取消关联。从活动发起时默认徒步及地图模式 |
| 显示模式 | 与 iOS 同级的“数据 / 地图”分段切换 |
| 开始运动 | 项目选择器（散步、慢跑、自由运动、徒步）和单个开始按钮，替代四个堆叠开始按钮 |
| 当前运动 | 时长、距离、步数、海拔和状态；暂停/继续及结束保存并排 |
| 地图 | 实时 GPS 分段轨迹、起点和当前点；历史记录提供“查看轨迹”和完成返回 |
| 提示 | 有异常时才显示提示与重试入口 |
| 历史记录 | 项目、时长、删除；继续、关联活动、距离/海拔、轨迹入口及当地日期/步数 |
| 同步 | 固定底部状态栏、进度及同步按钮，页面主体独立滚动 |
| 安卓专属设置 | 步长、读取重试、保存重试和系统设置收入右上角更多，不再固定堆在首页 |

安卓继续使用系统计步传感器，保留锁屏/后台自动暂停的既有约束；没有伪造 Apple 健康或手表连接能力。账户中已同步的 iOS/手表运动仍通过原公共接口进入同一历史列表。

## 轨迹及兼容性

- 开始数据模式不自动申请 GPS；用户明确开启地图后才启用轨迹。与 iOS 一致，已启用轨迹的当前运动切回数据视图不会停掉已授权记录，暂停时停止定位。
- 保存 routeEnabled；旧记录无此字段但包含轨迹时可兼容继续。继续历史记录仍创建新记录，不改写已完成记录。
- 轨迹复用活动地图既有 Leaflet/OSM 渲染方式；不向渲染器传入登录令牌或账户资料。只传入校验后的经纬度和分段，不拼接用户文本脚本。
- 暂停分段、超过一分钟定位间隔、无效坐标或时间倒序均断开连线，避免绘制未实际走过的路径。
- 地图加载失败不妨碍运动记录及原始轨迹保存；历史轨迹页使用完整可用高度。
- 时长展示按累计小时，不再在超过 24 小时时回绕。
- 继续复用 `/api/exercise/records` 的认证、账户隔离、幂等上传和删除标记，未新增平台专属数据源。原本机文件路径保持原样。
