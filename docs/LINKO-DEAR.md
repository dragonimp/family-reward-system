# Linko Dear：家庭与共同生活入口

Linko Dear 沿用现有家庭积分应用的安装身份和业务数据。家庭积分、亲子互动、成长记录、家族族谱继续由 FamilyReward API 管理。共同生活空间、活动、邀请和活动照片来自 Linko Social 的正式 API；Dear 不复制 Linko 的表和照片存储。

## 首批用户流程

- 家长从 Dear 进入孩子的亲子互动和家族族谱，也可以建立生活空间与活动，邀请亲友。
- 孩子使用用户中心身份进入 Dear 日常页；积分和手表业务仍由原有权限控制。
- 参与者通过用户名或七天链接确认加入活动。共同活动成员可互相申请好友，对方确认后才建立关系；任一方可解除。加入同一空间或活动不自动建立好友关系。
- 活动成员可发布、查看和删除自己写的生活日常文字，也可查看 Linko Social 中的活动照片和缩略图。照片与视频原文件通过 Linko Connect（MyVnc.Realtime）公共 SDK 的 DataChannel 在设备间传输，业务 API 仅保存索引、权限与下载请求。

## 身份与权限

Dear 的 `/api/dear/social/*` 是受限适配层。它使用 AgentIdentity.NativeClient 的 `NativeSsoClient`，将当前用户的 `happylife.ai` 令牌换为受众为 `linko.ai` 的服务令牌，再向 Linko Social 转发白名单接口。适配层不存储令牌，不创建账号，也不绕过 Linko Social 的空间和活动成员校验。

生产配置要求用户中心应用 `happylife.ai` 和 `linko.ai` 有同一个非空的独立 `CrossApplicationId`；两应用还必须对当前用户处于可用状态。用户中心缺少该授权时，接口明确返回 403，不回退到伪造身份或数据。

## 发布与验收

- 先核实用户中心跨应用授权及目标服务两个 `/auth/native/configuration` 的权威地址、Client ID，再部署 API 和网页。
- 真实验收使用两个不同用户中心账号：创建空间和活动、用户名邀请、对方确认、双方读取同一活动、分享照片后在 Dear 查看缩略图、撤销分享后消失。
- iOS 验收需分别检查 iPhone 和 iPad 的原生空间/活动/邀请/相册界面，Apple `VALID`、测试组可见性和实体设备操作分别记录。
- iOS 与网页使用同一 Connect file-v1 协议，设备原文件不经业务 WebSocket 中转；缩略图不等于原图。首版日常为活动内文字记录，尚无公开动态、评论或点赞；好友关系只在共同活动成员之间申请并双方确认。

## 1.2.65 活动与消息

- 活动列表标签右侧提供“新增”，以弹窗填写活动名称、日历日期与描述。列表维持活动日期倒序及纯日期显示。
- 活动详情依次展示概览、照片视频、合并的生活分享与打卡、位置和成员。照片卡片优先展示用户中心昵称。
- 下载请求通过用户中心正式 notifications:send 能力投递业务消息，并由各平台的原生推送通道提醒；iOS 使用 APNs，两个安装身份使用各自 Bundle ID 与设备令牌。锁屏只显示通用新消息提示，点击后读取当前用户的请求详情。
- 新版仅使用 Connect SDK；移除原文件 `/transfer` 中转接口。一次性迁移取消尚未完成的旧传输请求，保留照片、活动与完成记录。升级后重新请求即可。
- Connect SDK 提供有界分块、流式 SHA256、断点前缀核验、接收方持久化确认、取消与到期关闭；短期 ICE 到期通过重新授权连接续传。退出账号和停止共享会关闭活动连接。
- 业务配置与 SQL 迁移必须显式经 Atlas 执行，保留备份和唯一执行记录，不从服务启动执行。

推送令牌只通过 AgentIdentity Swift NotificationClient 登记到用户中心；照片源设备登记不传递推送令牌。Linko 自有 APNs 唤醒 Worker 已移除，通知服务只调用用户中心 SDK。
